# Отчёт проверки v0.1

## Статическая проверка

- `app.js`: синтаксис Node.js `--check` — OK.
- `engine-data.js`: синтаксис Node.js `--check` — OK.
- Локальная раздача через HTTP — OK.
- В проект встроено 283 ручных поля исходной очищенной книги.
- В расчётном ядре сохранены формулы и база смотрителей.
- Максимальная ссылка на строку в формулах — 660; модель выгружена до строки 700.
- В исходном калькуляторе обнаружено 806 формул и только 12 Excel-функций, совместимых с выбранным движком.

## Защита от ошибок пустых полей

Формулы в runtime-модели обёрнуты в `IFERROR(...,0)`. Это нейтрализует пустые неиспользуемые слоты (в исходной инструкции прямо сказано оставлять их пустыми) и не даёт ошибкам `MATCH` распространяться в общий итог. Пользовательские поля дополнительно проверяются на отрицательные/некорректные числа.

## Контрольный пример

В `engine-data.js` встроен полный набор 283 ручных значений из исходного заполненного файла «Надя 495» и эталонные результаты Excel:

- `T72` = 87.56503402600016
- `T73` = 362.42503402600016
- `AW1` = «Достаточно крови»
- `T15` = 62.44

При каждом запуске Mini App отдельный экземпляр расчётного движка автоматически прогоняет этот пример. Если результат расходится, приложение показывает красный статус и рекомендует не публиковать версию.

## Что нельзя проверить без реального Telegram-клиента

В текущем контейнере нет доступа к внешнему CDN и Telegram WebView, поэтому фактический runtime-тест `telegram-web-app.js` и HyperFormula в Telegram выполняется после публикации по HTTPS. Для этого встроен автоматический самотест, который запускается сразу при открытии приложения.
